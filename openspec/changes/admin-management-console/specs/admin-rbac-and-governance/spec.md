## ADDED Requirements

### Requirement: 管理员角色鉴权与路由隔离
系统 SHALL 支持基于角色的访问控制 (RBAC)。系统区分管理员 (ADMIN) 与普通用户 (USER)，并对所有 `/api/admin/**` 路由实施服务端强制鉴权拦截，非 ADMIN 身份禁止访问。

#### Scenario: 管理员成功访问管理接口
- **WHEN** 携带有效 JWT 且对应用户角色为 `ADMIN` 访问 `/api/admin/**`
- **THEN** 系统正常处理并返回相应业务数据

#### Scenario: 普通用户或未登录访问被拒绝
- **WHEN** 未携带 Token 或 Token 对应的用户角色为 `USER` 访问 `/api/admin/**`
- **THEN** 系统返回 HTTP 403 Forbidden 或 401 Unauthorized 错误提示

### Requirement: 用户列表查询与状态展示
系统 SHALL 提供用户管理查询接口，返回系统中所有已注册用户的用户名、用户角色、账号状态 (NORMAL / DISABLED) 及创建时间。

#### Scenario: 查询用户列表
- **WHEN** 管理员进入用户管理面板请求用户列表
- **THEN** 系统返回包含用户详细属性的列表，前端以表格形式展示

### Requirement: 用户访问授权与停用封禁
系统 SHALL 允许管理员对指定普通用户执行“授权访问”或“取消授权访问 (停用)”操作。账号被停用后，该用户无法登录，且已签发 Token 再次请求自选等接口时被立即拦截。

#### Scenario: 管理员停用普通用户
- **WHEN** 管理员点击某用户的“取消授权 / 禁用”按钮
- **THEN** 系统将该用户的状态置为 `DISABLED`，且该用户的所有后续请求均返回账号已停用提示

#### Scenario: 管理员恢复普通用户授权
- **WHEN** 管理员点击处于禁用状态用户的“恢复授权 / 启用”按钮
- **THEN** 系统将该用户的状态恢复为 `NORMAL`，用户可重新正常登录和使用系统

### Requirement: 调阅普通用户自选基金
系统 SHALL 允许管理员调阅任意普通用户的自选基金列表，并获取对应的实时净值估值数据，以便客服支持与技术排查。

#### Scenario: 查看目标用户的自选基金
- **WHEN** 管理员在用户列表中点击目标用户的“查看自选”操作
- **THEN** 系统弹出或加载该用户的所有自选基金代码、基金名称及实时估值列表，仅供管理员只读查看

### Requirement: VIP 会员资格管理与权益校验
系统 SHALL 支持区分普通用户与 VIP 会员，并允许管理员在后台直接为指定用户开通或取消 VIP 资格。系统提供可复用的 VIP 权益校验机制，为未来只允许 VIP 用户访问的高级功能提供权限拦截支持。

#### Scenario: 管理员为普通用户开通 VIP
- **WHEN** 管理员点击某用户的“设为 VIP 会员”操作
- **THEN** 系统更新该用户的 `is_vip = true`，前端列表即刻展示 👑 VIP 标识，该用户后续可正常使用 VIP 专属功能

#### Scenario: 管理员取消用户的 VIP 资格
- **WHEN** 管理员点击某 VIP 用户的“取消 VIP”操作
- **THEN** 系统将该用户的 `is_vip` 置为 `false`，降级为普通会员，其 VIP 专属权益立即失效

#### Scenario: 普通用户尝试访问 VIP 专属功能
- **WHEN** 非 VIP 且非 ADMIN 的普通用户尝试调用标记为 VIP 的功能接口
- **THEN** 系统拦截请求并返回 HTTP 403 错误，提示“该功能仅对 VIP 会员开放，请联系管理员开通”
