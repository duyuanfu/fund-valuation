## Context

当前系统已建立完整的基金行情、实时估值、持仓管理（`user_position`）与持仓重仓股明细（`fund_holding`）数据链路，并已内置通用大模型配置体系（`sys_vision_config`，支持 OpenAI / 智谱兼容协议）。
然而，用户在配置多只基金时无法看清底层真实资产暴露，易出现“伪分散”风险（例如持有的5只基金第一大重仓股均为腾讯或贵州茅台）。用户迫切需要一个既能直观穿透看清底层资产、又能给出客观量化健康分并结合 AI 生成智能体检报告的功能。

## Goals / Non-Goals

**Goals:**
- **穿透透视计算**：以用户持有的基金份额/市值为权重，聚合穿透出整个组合的 Top 10 底层核心股票、持仓金额与占比，透视股票/债券/混合资产大类比例与主要行业分布。
- **底层重合度分析**：计算用户持仓各基金之间的重仓股重合度矩阵，识破虚假的资产分散。
- **客观量化健康分（0-100）**：建立集中度赫芬达尔指数（HHI）、单股票极值偏离、单行业暴露度等量化评分模型。
- **AI 智能投顾体检报告**：将量化透视指标组装为结构化 Prompt，调用已配置的大模型接口，生成结构清晰的诊断综述、潜在隐患与调仓建议，具备缓存机制。
- **现代化可视化展示**：在持仓页提供「组合透视」与「智能诊断」视图，集成 ECharts 环形图与横向条形图。

**Non-Goals:**
- 不支持盘中毫秒级股票穿透实时变动（基金前十大重仓股严格依公募基金季度法定披露数据为准）。
- 不提供直接的自动量化调仓买卖交易（仅提供投教与辅助决策建议）。

## Decisions

### 1. 组合穿透透视：自研内存聚合算法 vs 外部第三方 API
- **选择**：自研本地内存加权聚合算法。
- **考量与对比**：
  - 外部金融接口：市面上极少有允许上传用户私密持仓清单并免费返回穿透透视数据的第三方开放 API，且存在用户持仓隐私泄露与网络抖动风险。
  - 自研实现：系统本地已拥有 `fund_holding` 季度前十大重仓数据与 `user_position` 持仓金额。单用户穿透聚合仅为 10~30 只基金与数百个持股权重的加权求和，Java 内存运算耗时 < 10ms，零外部依赖，数据隐私 100% 安全。

### 2. 诊断架构：量化规则引擎 (硬指标) + 大模型投顾 (软文案) 双层协同
- **选择**：双层混合架构。
- **考量与对比**：
  - 纯规则引擎：打分客观准确，但生成的评语生硬机械，缺乏个性化互动与深度逻辑。
  - 纯大模型端到端：大模型计算数学数值和百分比容易发生“幻觉”，且直接让大模型算聚合容易算错。
  - 双层混合：第一层由 Java 引擎精确计算出“健康分”、“集中度 HHI”、“前三大行业占比”、“重仓股重合度”等确凿数据；第二层将这些确凿数据送入 LLM，由大模型负责输出兼具专业性与易读性的投顾诊断报告。

### 3. AI 报告缓存与容错降级
- **选择**：基于持仓特征指纹（MD5）的缓存机制 + 大模型离线平滑降级。
- **考量与对比**：
  - 用户持仓未发生增删改时，多次点击无需重复调用 LLM API，节省 Token 与响应时间。
  - 若系统未配置大模型 API Key 或外部接口超时，前端仍完整展示 100% 的量化图表与规则风险标签，仅提示“AI 深度体检处于免打扰状态”，保证基础功能高可用。

## Risks / Trade-offs

- **[季度持仓披露滞后性]** → 公募基金重仓股仅在每季末披露。在前端界面显式标注“重仓股披露期：2026Q2”，并提供提示浮窗，让用户知悉数据口径。
- **[大模型 API 调用耗时]** → 前端采用加载骨架屏；量化图表率先 50ms 极速呈现，AI 报告异步流式或独立卡片加载，避免阻塞主视图。
- **[部分债券型或货币型基金无个股持仓]** → 在穿透计算时，非股票类资产单独归入“固收与现金类”大池，计算资产大类配比，不影响股票集中度评分。
